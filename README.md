# SaveHub

珍藏每一次冒险。一个基于 **Electron + React + TypeScript** 的本地游戏存档管理器，支持 Windows 与 macOS Apple Silicon。

## 开始使用

Windows：打开 `release/1.1.4/win-unpacked/SaveHub.exe`，或使用 `release/1.1.4/` 下的安装包、便携版。整个 `win-unpacked` 文件夹需要一起保留，不能只复制其中的 EXE。先关闭正在运行的旧版，再打开新版；已有资料库可直接使用。

1. 选择游戏，打开「游戏设置」。确认当前系统的**游戏存档根目录**与**要备份的相对路径**。
2. 关闭游戏，点击「创建新存档」，填写名称与备注。
3. 点击某份存档的「读档」，确认游戏及会写入文件的云同步已关闭。应用先自动保存当前进度并校验，成功后才恢复选中的内容；自动保存失败会停止读档。
4. 要撤销读档，在时光轴右侧的「读档恢复点」中找到 `读档前 · …`，点击恢复即可。

预置游戏可编辑或移除，也可以添加任意游戏。图标支持内置图形与本地 PNG / JPG / WebP / ICO 图片。图片导入后会复制到配置中，不依赖原文件继续存在。

## 参考脚本与对应关系

已阅读这三个目录中的 `save.sh` / `load.sh`：

| 游戏 | 原脚本的游戏根目录（target） | 备份项目（array） |
| --- | --- | --- |
| 杀戮尖塔 | `D:\Steam\steamapps\common\SlayTheSpire` | `betaPreferences`、`preferences`、`saves` |
| 艾尔登法环 | `%USERPROFILE%\AppData\Roaming\EldenRing` | `Steam账户ID` |
| 黑暗之魂 II | `%USERPROFILE%\AppData\Roaming\DarkSoulsII` | `Steam账户ID` |

首次在 Windows 启动时，会尝试读取用户桌面对应目录的 `save.sh`，只解析 `source` / `target` / `array` 的字面量，**不会执行脚本**。没有脚本时使用上述根目录预设；艾尔登法环与黑暗之魂 II 不预置账号目录，需在「游戏设置」中填写自己的 `Steam账户ID` 目录。路径、账号目录都可以手动修改。

旧脚本的 `source` 对应原备份目录。应用创建的新存档使用独立资料库和 UUID，不再根据目录数量决定编号，也不会覆盖旧的 `ArchiveFile…`。

「导入旧存档」会复制旧目录内所有 `ArchiveFile…` 子目录，兼容 `ArchiveFile0`、`ArchiveFile10th-DLC-1st-1level` 等自定义后缀。「导入存档」还接受单个旧存档目录、以名称命名的单份导出目录及其批量导出根目录，也兼容旧版 `manifest.json` / `collection.json` 导出。发现重复时，在一个对话框中列出所有重复项，每项可独立选择**覆盖、跳过或两者并存**，也可批量设置后逐项调整，最后点击「执行导入」。确认前不会写入本批任何存档，取消会取消整批导入。

同一游戏中，再次导入同一个来源目录会识别为重复，即使该来源的内容已经更新；不同来源目录不会仅因内容相同而合并。默认选择跳过。覆盖先复制并校验，再替换选中的已有记录，保留其 ID、创建时间和收藏标记；同一来源已有多份记录时，可指定覆盖目标。保护存档、回收站记录和读档恢复点不能被覆盖，可选择跳过或两者并存。两者并存会生成独立 ID，并在名称后添加 ` (2)`、` (3)` 等编号。覆盖失败会还原原记录，意外中断后在下次启动时恢复。结果分别列出新导入、已覆盖、两者并存、已跳过与失败；导入源文件始终保留。

## 功能

- 多游戏独立配置与独立存档库，Windows / macOS 路径分别保存。
- 一次备份多个文件或目录，递归保留空目录、文件内容与修改时间。
- 存档命名、备注、收藏、保护标记、搜索、完整性校验、导入、导出。
- 点击存档名称、创建时间、文件大小表头切换正序或倒序，默认创建时间倒序；名称支持自然数字排序。
- 勾选单份或全选当前列表，批量保护、取消保护、移入回收站、找回、导出；保护操作分别提供“所选”和“全部”两个按钮。
- 收藏仅是星标，允许删除。单份和批量删除确认会醒目提示已收藏记录的数量，批量清单逐项标出“已收藏”，确认后正常移入回收站并保留收藏标记。
- 保护存档禁止删除；所选记录中只要含有保护存档，整批删除就会被拦截，须先取消保护。保护和取消保护不会生成副本。
- 「全部存档」包含所有未删除的手动和导入记录，包含已收藏、保护存档；两者只是筛选标记，不移动记录或产生副本。回收站、读档恢复点不计入其中。
- 批量导出只选一次目标目录；「导出全部」导出当前标签页中的全部记录，不受搜索影响。在已收藏、保护存档和回收站标签页中，分别只导出对应标签页的存档。
- 恢复前自动创建独立的读档恢复点，事务式替换、失败回滚、下次启动恢复未完成事务。
- 读档恢复点支持多选、全选后移除；回收站和已移除的恢复点支持多选、全选后找回或永久删除。永久删除须二次确认，真实移除磁盘文件，无法找回。
- 移除游戏保留所有备份，可在设置中找回。
- 四种持久化主题：宣纸水墨、通透科技、霓虹赛博朋克、磨砂玻璃。右上角为唯一主题入口；再次点击返回上次页面，保留游戏、筛选、搜索、排序、勾选和滚动位置。
- 路由、筛选、排序、主题与弹窗变化带过渡效果；遵循系统的减少动态效果设置。
- 本地文件处理，不需要账号或服务器。不会自动同步、定时备份或检测游戏进程。

## 存档与标记

每份手动创建或导入的存档只有一个 ID 和一份原始内容。收藏、保护、回收站修改这份记录的标记，切换标记不会生成副本。

| 视图 | 显示范围 |
| --- | --- |
| 全部存档 | 所有未删除的手动或导入存档，包含已收藏和保护记录；不含回收站及读档恢复点 |
| 已收藏 | 带收藏标记且不在回收站的记录；可同时有保护标记 |
| 保护存档 | 带保护标记且不在回收站的记录 |
| 回收站 | 已移除的手动或导入记录；可找回并保留原有标记，也可确认后永久删除 |
| 读档恢复点 | 读档前自动保存的进度，独立展示，不计入全部存档；可恢复游戏进度或移除 |
| 已移除的恢复点 | 从读档恢复点移除的记录；可找回到恢复点列表，或确认后永久删除 |

在存档的「更多操作」中添加或取消保护标记。侧栏、游戏卡片、时光轴及全部存档统计均采用「全部存档」范围。收藏或保护前后，记录的 ID、文件目录和数量不变；同一份记录可同时出现在全部存档、已收藏、保护存档三个视图中。保护标记限制普通删除和永久删除，不限制读档和导出；收藏仅用于标记和筛选，不阻止删除。

回收站中的存档不能修改保护标记，工具栏不显示「所选保护／所选取消保护」和「全部保护／全部取消保护」按钮，单份菜单中的保护操作仍禁用；需要先找回，再标记保护。旧版本已在回收站中标记保护的记录也需先找回，才能取消保护。批量保护请求只要包含回收站记录，就会在修改任何记录前停止。

「全选当前列表」只选择当前搜索和筛选后可见的有效存档；切换筛选或搜索会清空选择，每个游戏独立保留列表状态。批量保护的“所选”按钮只处理勾选项；“全部”按钮处理当前标签页的全部存档，不受搜索影响。例如，在「已收藏」中只修改收藏记录的保护标记；在「保护存档」中可一次取消该标签页全部记录的保护，取消后这些记录退出该标签页。单份收藏与取消收藏仍通过每行星标操作。

在回收站以外的标签页，两个保护按钮都按各自范围内的记录状态切换：

| 范围内的状态 | 所选按钮 | 全部按钮 | 点击结果 |
| --- | --- | --- | --- |
| 全部已保护 | 所选取消保护 | 全部取消保护 | 统一取消保护 |
| 全部未保护 | 所选保护 | 全部保护 | 统一添加保护 |
| 保护与未保护混合 | 所选保护 | 全部保护 | 统一添加保护 |
| 没有记录 | 所选保护（禁用） | 全部保护（禁用） | 不执行操作 |

保护操作使用绿色盾牌勾选图标，取消保护使用琥珀色盾牌划线图标，两类按钮的文字、边框及背景颜色均有区别，四种主题均适配。

「导出所选」也能导出保护或回收站中的完整记录。「导出全部」始终按当前标签页的完整范围导出，包括被搜索隐藏的记录；当前标签页没有记录时禁用。回收站中即使没有正常存档，也能导出回收站的完整记录。读档恢复点仍通过独立入口导出。

普通存档删除后进入「回收站」；读档恢复点移除后进入「已移除的恢复点」。这一步只改标记，文件仍在。两个已删除列表均可勾选多份或全选，再点击「找回所选」或「永久删除所选」；恢复点的正常列表也支持多选和全选后移除。「找回」只恢复列表记录，不把内容写入游戏；只有「读档」或恢复点的「恢复」会替换游戏进度。

永久删除的确认框会列出将删除的记录并明确提示“无法恢复”。包含收藏时继续醒目标记，不增加额外阻断；包含保护时必须先找回并取消保护，再移入回收站删除。永久删除成功后，备份目录、原始内容及记录清单一并移除，不能在应用中再次找回，游戏当前存档不受影响。

所有导出（单份、所选、当前标签页全部记录，以及读档恢复点）都会在所选位置新建一个「游戏名-存档导出」外层文件夹。内部保留以存档名称命名的文件夹和导入清单，名称文件夹内就是原始游戏存档。例如：

```text
所选导出目录/
  游戏名-存档导出/
    A/                       存档 A 的实际文件与目录
    B/                       存档 B 的实际文件与目录
    C/                       存档 C 的实际文件与目录
    .savehub-exports/         导入所需的名称、标记与校验清单
```

每次导出生成独立的外层文件夹，已有同名文件或目录时自动加 ` (2)`、` (3)` 等后缀；同一批次内的重名存档也会自动编号，不覆盖现有文件。文件夹名称中的非法字符会替换，原始游戏名和存档名称仍保存在清单中。所有内容先复制并校验，再输出名称目录；正常失败会清理本次输出，保留已有文件。移动或分享整个外层文件夹即可保留原名称、备注、收藏与保护标记，导入时直接选择这个文件夹即可；也可选择里面的单份名称文件夹。旧版没有外层文件夹的命名导出及 `manifest.json` / `collection.json` 导出仍可导入。已导出的回收站记录导入后不再标记为已删除。

1.0.0 的自动保护副本仍在原位置，自 1.1.0 起显示在「读档恢复点」，不复制或迁移文件。1.1.2 继续保留「保护存档」手动标记与「读档恢复点」自动备份的独立分类，并将禁止删除的规则从收藏调整为保护。1.1.3 将全部存档视图统一为包含收藏与保护标记的记录，并新增批量永久删除与找回。1.1.4 要求先找回回收站记录才能修改保护标记，并为所有导出增加独立外层文件夹。已有标记和原始存档内容不需要迁移。

## 存储与恢复规则

默认资料库位于 Electron 的 `userData` 目录，精确路径在「设置与关于」中显示：Windows 通常为 `%APPDATA%\SaveHub`，macOS 通常为 `~/Library/Application Support/SaveHub`。开发模式使用项目内的 `.local-data`。可用 `SAVEHUB_DATA_DIR` 指向单独的资料库进行测试或本地部署；不要让两个进程共用同一资料库。

```text
SaveHub/
  library.json                    游戏资料和主题
  library.json.previous           上一次配置
  vault/<game-id>/
    game.json                     自定义游戏资料
    snapshots/<snapshot-id>/
      manifest.json               路径、时间、备注、标记、SHA-256 校验清单
      payload/                    原始存档内容
  transactions/                   恢复事务日志
  import-transactions/            导入覆盖事务日志，完成后清理
```

存档不是压缩包，可以直接检查其文件。读档只替换配置的相对路径，其他游戏文件不受影响；被替换目录内新出现的文件会移除，以保持完整恢复语义。读档恢复点也会记录原本不存在的路径，恢复它时这些路径会重新不存在。

复制先写入暂存目录，再比较源文件、复制文件和校验清单；验证成功后才提交。恢复先验证备份，再生成自动恢复点，再在目标磁盘暂存，通过逐项重命名替换。恢复失败时还原原文件；异常中断后根据事务日志恢复。失败暂存目录和日志保留供诊断。它们可能占用额外空间。普通移除只改变记录状态，不释放文件；在回收站或已移除的恢复点中执行永久删除才释放相应备份内容。应用不会自动清理恢复点。

永久删除前检查整批记录身份、删除状态、保护标记和路径安全。每份记录开始删除前持久化清理状态；若文件占用或应用中断，重新打开后仍显示“永久删除未完成”，可再次永久删除以继续清理。已开始清理的记录可能不完整，禁止找回、编辑、保护或导出；批量结果会分别列出成功与失败。

为了避免越界写入，拒绝绝对的备份项、`..`、父子路径重叠、大小写冲突、Windows 保留名称、符号链接与目录联接。选中的根目录和子路径必须可读写；资料库不能与要备份的内容重叠。目录在磁盘上尚未存在时，请先启动游戏创建存档，或手动建立正确目录。

关闭游戏与云同步十分重要：应用会检测复制和替换前后的变化，但不能阻止其他进程同时写入。系统权限错误、磁盘故障或外部程序持续修改文件仍可能需要人工恢复；应用会保留保护副本与事务记录。

## Windows 与 macOS

使用同一套 Electron 和 Node 文件实现，无 Bash、盘符替换命令或 `rm -rf` 依赖。macOS 的预设路径留空，需要选择实际存档位置；应用兼容 macOS 不代表游戏本身有 macOS 原生版本。通过 Wine / CrossOver 运行的游戏可以选择兼容层中的实际目录。SaveHub 不转换游戏存档格式。

最低系统要求依据当前 Electron 运行时：Windows 10 及以上，macOS 13 Ventura 及以上。Mac 发行目标只配置 **arm64**，不构建 Intel 版本。Windows 当前提供 x64 版本。

2026-11-03 已在 Apple Silicon Mac（macOS 26.6）完成源码测试、四项 GUI 测试和 `pnpm dist:mac` 打包，并在打包后的 `.app` 上通过基础 GUI 测试。Mac 包使用 ad-hoc 签名（`build.mac.identity: "-"`），可避免未签名包下载后被提示“已损坏”；其他 Mac 首次打开仍需在“隐私与安全性”中允许。发布给其他用户前，需要配置 Apple Developer 签名与公证（届时删除 `identity: "-"`）；本项目未包含证书或公证凭据。Windows 包也未配置代码签名。

```sh
pnpm test:interactions   # 主题返回、批量操作、标记、排序与过渡验证
pnpm test:deletion       # 回收站和恢复点的批量找回、物理删除及中断重试
pnpm test:import         # 重复导入的逐项选择、混合执行、取消与四主题界面
pnpm pack:win            # Windows 解包版
pnpm dist:win            # Windows 安装版 + 便携版
pnpm pack:mac            # macOS arm64 解包版（.app）
pnpm dist:mac            # 在 Mac 上构建 arm64 DMG + ZIP
pnpm test:portable       # Windows 便携版的解包、启动与存读档验证
pnpm audit:release       # 核对 Windows 包内代码与发行文件摘要
```

构建完成后 `pnpm start` 可使用 Electron 打开生产界面。所有依赖版本已固定，并提供 `pnpm-lock.yaml`。安装时会获取官方 Electron 运行时；网络不通时可参考 [Electron 安装文档](https://www.electronjs.org/docs/latest/tutorial/installation) 的镜像配置，文件仍使用包内的官方摘要校验。

`.github/workflows/build.yml` 提供 Windows 和 macOS 构建工作流，上传安装包供下载，不会自动发布 Release。该文件仅提供配置，尚未在远端执行。

```text
electron/storage.mjs       备份、完整恢复、校验、事务回滚、导入导出
electron/presets.mjs       三个游戏的脚本字面量解析与预设
electron/main.mjs          Electron 窗口、原生对话框、IPC 权限边界
electron/preload.cjs       最小化、明确列举的 renderer API
src/App.tsx               游戏库、存档时光轴、编辑表单与主题选择

src/RestorePoints.tsx     恢复点与已移除恢复点的选择、找回及删除
src/ImportDialog.tsx      重复导入的逐项处理选择、批量设置及结果
src/motion.ts             页面过渡及减少动态效果适配
src/art.tsx               本地 SVG 场景与游戏图形
src/styles.css            布局与交互样式

scripts/smoke.mjs          独立测试资料库上的 Electron 端到端检查
scripts/interactions.mjs  主题返回、选择排序、批量文件操作与状态语义检查
```

Electron 启用 context isolation、sandbox，关闭 Node integration，拒绝导航和额外窗口，并校验 IPC 主窗口与 frame 来源，遵循 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)。渲染层不能直接访问文件系统。主题与插画均随应用打包，无在线字体或图片依赖。
